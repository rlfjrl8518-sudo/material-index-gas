# material-index-gas

한화손해보험 DA 소재 인덱싱 시스템 (Google Apps Script + Google Sheets + Google Drive)

- **소재 등록 / 소재 분석 / 보고서 / AB 테스트 / 설정 관리**: 매체 성과 데이터를 소재 단위로 인덱싱·분석
- **소재 검수** (신규): 이미지 소재 속 문구(상품명·심의필·기타 필수 문구)를 사용자가 입력한 기준값과 비교해 불일치를 찾아주는 내부 검수 도구

모든 화면은 하나의 웹앱(`Index.html`)에서 탭으로 전환됩니다. 스프레드시트를 열면 상단에 커스텀 메뉴(`소재 인덱싱`, `이미지 검수`)가 추가됩니다.

## 운영 구조 (2026-10-28~)

- **대시보드는 Vercel**(https://material-index-nine.vercel.app)에서 서비스한다. `api/`·`lib/`가 기존 `.gs`를 고치지 않고 Node에서 그대로 실행하는 GAS 호환 레이어다(`lib/gas.js`: SpreadsheetApp·DriveApp·UrlFetchApp·Properties 등). 시트·드라이브 접근은 playddmt1 계정의 OAuth refresh token(Vercel 환경변수)으로 한다.
- **데이터는 지금처럼 구글시트**. RAW 붙여넣기 → 시트 메뉴 `소재 인덱싱 > 통합 적재`는 그대로(시트에 붙은 Apps Script가 실행). 기존 Apps Script 웹앱도 예비로 살아 있다.
- 배포: `vercel deploy --prod` (Vercel) / `clasp push --force --user playddmt1` (시트 메뉴용 Apps Script). `.claspignore`가 `api/`·`lib/` 등을 제외한다.
- Script Properties 대신 숨김 시트 `_properties`에 설정을 저장한다(없으면 같은 이름의 환경변수). 쓰기 호출은 `작업이력` 시트에 남는다.
- 매일 08시(KST) Vercel Cron → `sendDailyDigest`(설정 관리 > API 키의 `아침 요약 웹훅 URL`이 있을 때만).
- 로그인: `APP_PASSWORD`(비밀번호) / `GOOGLE_LOGIN_CLIENT_ID` + `ALLOWED_EMAILS`·`ALLOWED_DOMAINS`(구글 로그인, 설정 시).

## 파일 구성

```
Code.gs                 웹앱 진입점(doGet), 메뉴, 시트 초기화, Drive 업로드 공통 함수, API 키 관리
InspectionConfig.gs      소재 검수 - 검수기준/검수결과/검수이력 시트 정의, 기준값 읽기
InspectionVision.gs      소재 검수 - Gemini(Vertex AI) 이미지 분석, ZIP 압축 해제
InspectionCompare.gs     소재 검수 - 문자열 정규화/비교/판정, 수정 요청 문구 생성
InspectionService.gs     소재 검수 - 업로드~검수~결과조회 오케스트레이션, 대량 처리(배치/트리거)
Registration.gs          등록 대기열, AI 태그·심의필 추천, 일괄 저장, 심의필 백필
Insights.gs              오늘 할 일(getActionItems), 아침 요약, 제작 브리프
api/ lib/                Vercel 함수 + GAS 호환 레이어 (Apps Script에는 올라가지 않음)
Index.html               단일 페이지 웹앱 (탭: 소재 등록/분석/보고서/AB테스트/설정관리/소재 검수)
appsscript.json          매니페스트 (oauthScopes에 spreadsheets/drive/script.external_request 포함)
```

## 설치

1. 이 저장소 내용을 Apps Script 프로젝트에 그대로 복사합니다 (Apps Script 편집기에서 파일을 하나씩 만들거나, `clasp push` 사용).
2. `Code.gs` 상단의 `SHEET_ID`가 실제 사용할 스프레드시트 ID와 일치하는지 확인합니다.
3. 스프레드시트를 열고 새로고침 → 상단 메뉴에 `소재 인덱싱`, `이미지 검수`가 보이면 정상입니다.
4. 메뉴 `소재 인덱싱 > 시트 초기화` 실행 → 기존 시트들과 함께 `검수기준` / `검수결과` / `검수이력` 시트가 자동 생성됩니다.
   (또는 `이미지 검수 > 검수 시트 초기화`로 검수 시트만 따로 생성 가능)
5. 웹앱으로 배포되어 있지 않다면 Apps Script 편집기에서 `배포 > 새 배포 > 웹 앱`으로 배포합니다. (`appsscript.json`에 이미 `webapp.access: ANYONE`, `executeAs: USER_DEPLOYING` 설정되어 있음)

## AI 설정 (Gemini, Vertex AI)

소재 분석 탭의 AI 인사이트·후속 질문 챗봇과 소재 검수 탭의 이미지 분석이 모두 Vertex AI의 Gemini(`google/gemini-3.5-flash`, `InspectionVision.gs` 상단 `AI_MODEL`)를 사용합니다. API 키는 없고, 스크립트 실행 계정(웹앱은 배포 계정)의 OAuth 토큰으로 호출합니다.

1. GCP 프로젝트에서 **Vertex AI API**를 사용 설정합니다 (결제 계정 연결 필요).
2. 배포 계정에 그 프로젝트의 **Vertex AI 사용자**(`roles/aiplatform.user`) 권한을 줍니다.
3. Apps Script 편집기 `프로젝트 설정 > Google Cloud Platform(GCP) 프로젝트`에서 같은 프로젝트 번호로 변경합니다.
4. 대시보드 `⚙️ 설정 관리` → `🔑 API 키` → `GCP 프로젝트 ID`에 프로젝트 ID를 입력합니다 (또는 스프레드시트 메뉴 `이미지 검수 > GCP 프로젝트 설정`, Script Property `GCP_PROJECT_ID`).
5. 편집기에서 아무 함수나 한 번 실행해 새 권한(`cloud-platform`)을 승인합니다.

## 검수 기준 입력

스프레드시트 메뉴 `이미지 검수 > 검수 기준 시트 열기`로 `검수기준` 시트를 엽니다.

| 항목 | 설명 |
|---|---|
| 상품명·보종명 / 심의필 / 기타 필수 문구 1·2 | 사용 여부 체크박스 + 기준 문구 입력 (선택 입력 — 체크 안 하면 검사하지 않음) |
| 로고 | 사용 여부 체크 시, 값 칸에 기준 로고 이미지의 Drive 공유 링크 또는 파일 ID 입력 |
| 폰트 | 사용 여부 체크 시, 값 칸에 기준 폰트명 입력 (참고용 — 최종 결과에는 영향 없음) |
| 띄어쓰기 정확히 비교 / 줄바꿈 무시 / 영문 대소문자 구분 / 특수문자 정확히 비교 | 비교 옵션. 심의필의 숫자·하이픈은 특수문자 옵션과 무관하게 항상 정확히 비교됩니다 |

## 사용 흐름

1. 대시보드(웹앱) → `🔍 소재 검수` 탭
2. 현재 검수 기준 확인 (기준은 시트에서만 수정 가능, 이 화면은 읽기 전용)
3. 이미지(JPG/JPEG/PNG/WEBP) 또는 ZIP 파일을 업로드 존에 드래그하거나 선택
4. `검수 시작` 클릭 → 브라우저가 Google Drive에 직접 업로드(기존 소재 등록 탭과 동일한 방식) → 서버가 문구 인식·비교·판정
5. 진행률/처리 완료 건수가 실시간으로 표시되고, 결과 테이블에 파일별 판정과 수정 요청 문구가 채워집니다
6. `확인 필요` 항목만 재처리하려면 `확인 필요 항목 재처리` 버튼 사용
7. 모든 원본 이미지는 Drive의 `이미지소재검수/YYYY-MM-DD_검수번호/원본` 폴더에 보관되며 자동 삭제되지 않습니다

## 대량 처리

- 한 번에 최대 20장을 배치로 처리하고, 남은 이미지는 시간 기반 트리거(`continueInspectionBatch`)가 5초 뒤 이어서 처리합니다.
- 진행 상태는 이미 처리된 이미지 수(검수결과 시트의 기존 행)와 원본 Drive 폴더를 대조해서 판단하므로, 브라우저 탭을 닫아도 서버에서 계속 진행됩니다. 대시보드에서 검수번호로 다시 진행률을 조회할 수 있습니다.
- 동시 실행은 `LockService`로 방지합니다.

## 테스트 방법

Apps Script 서버 코드는 브라우저 없이도 편집기에서 개별 함수를 실행해볼 수 있습니다.

1. `initInspectionSheets` 실행 → 시트 3개 생성 확인
2. `검수기준` 시트에 상품명만 체크 + 값 입력, API 키 등록 후 임의 이미지를 Drive에 올리고 `analyzeImageWithOpenAI(fileId, getInspectionCriteria())`를 편집기에서 직접 실행해 응답 JSON 확인
3. `normalizeText`, `diffText`, `judgeField` 등은 순수 함수라 편집기 로그(`Logger.log`)로 간단히 단위 테스트 가능
4. 웹앱 배포 후 대시보드 `소재 검수` 탭에서 이미지 1~2장으로 전체 플로우(업로드 → 판정 → 수정요청 문구 → 결과 시트 기록) 확인
5. 이미지 10장 이상 + ZIP 파일을 섞어 업로드해 배치/트리거 동작과 진행률 폴링 확인
6. 글씨가 뭉개진 저해상도 이미지로 `확인 필요`(판독 불가 글자 `?`) 처리와 재처리 버튼 동작 확인

## 현재 구현 한계

- **실행/테스트 미검증**: 이 코드는 원격 저장소 파일 편집만으로 작성되었고, 실제 Apps Script 런타임에서 실행해보지 못했습니다. Apps Script 편집기에 붙여넣은 뒤 위 테스트 절차로 반드시 검증이 필요합니다.
- **판독 방식**: Gemini가 기준값을 모른 채 이미지를 두 번 독립 판독하고, 비교는 코드가 합니다. 두 판독이 다르거나 읽을 수 없는 글자(`?`)가 있으면 `확인 필요`로 넘겨 틀린 소재가 `정상`으로 통과하지 않게 합니다. 사람 눈으로도 읽기 어려운 글씨는 자동 판정 대신 `확인 필요`가 됩니다. 커스텀 지시사항에 적힌 기준값은 AI에 보내기 전에 가립니다.
- **로고/폰트 판정**: MVP 수준으로 존재 여부·전반적 유사도만 봅니다. 위치·크기·정밀 비교는 지원하지 않으며, 폰트 판정은 참고용으로만 쓰이고 최종 결과에 반영되지 않습니다.
- **기타 필수 문구 판정 방식**: confidence가 없는 `allTexts` 목록에 기준 문구가 포함되는지로 판정합니다(포함 매칭). 상품명·심의필처럼 confidence 기반 정밀 판정은 아닙니다.
- **비용/한도**: Vertex AI 사용량만큼 GCP 프로젝트에 과금됩니다. 429/5xx가 나면 자동 재시도하고, 그래도 실패한 이미지는 오류로 표시됩니다.
- **동시 실행**: 이 도구는 한 번에 검수 1건이 진행 중이라고 가정합니다(내부 업무용 규모). 여러 검수를 동시에 진행하면 트리거 처리 로직이 마지막 활성 검수만 이어받습니다.
- **Drive 업로드 권한**: 웹앱이 `executeAs: USER_DEPLOYING`으로 배포되어 있어, 실제로는 배포한 계정의 Drive/Sheets 권한으로 모든 요청이 처리됩니다(기존 소재 등록 기능과 동일한 방식). 검수이력의 "실행 사용자"도 뷰어가 아니라 배포 계정 기준으로 기록될 수 있습니다.
